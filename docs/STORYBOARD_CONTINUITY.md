# 分镜连续性与视频衔接

本功能面向**同一集内相邻的视频段落**。每个段落内部可以有多个子镜头，衔接约束作用于前段最后一个子镜头和后段第一个子镜头。目前不自动跨集引用上一集的视频。

## 页面使用

1. 已有分镜可点击顶部“分析衔接”，补充 AI 建议、起止状态和来源关系。这一步只更新衔接元数据，保留分镜描述、视频提示词和已生成的视频；人工选择会保留，新的 AI 分析只更新建议。
2. 在每段的衔接编辑器检查生效策略、来源段落和起止状态。策略保存到服务器，刷新后保留；并发修改发生版本冲突时，先刷新获取最新值再保存。
3. 批量生成前查看预检结果，必要时加入前置镜头。同批选中的来源绑定本批新任务，后段等待确切的前段视频下载完成；动作续接还需要前段上下文验证通过。
4. 对已生成的片段修改策略不会自动重新生成。需要采用新策略时，再明确提交生成；新任务等待或失败时，旧视频仍可播放。
5. 在“拼接导出”选择视频和连接方式，检查预估时长。接缝原片预览展示前段结尾与后段开头，最终效果以导出的成片为准。

## 调整分析规则

在“设置 → Agent → 镜头衔接分析”中可以编辑独立的 System Prompt 和 `continuity-planner` Skill，保存后下次点击“分析衔接”即生效，无需重启。System Prompt 定义分析目标、工作流程和默认判断原则；Skill 补充镜头关系、起止状态和各类接续模式的具体判断标准。新建在 `continuity-planner/` 下的子技能也会一起加载。

配置提供中文、英文、日文和韩文版本，分析时按内容语言读取；缺少对应语言版本时回退基础版。模型选择顺序是本次请求指定的模型、基础 Prompt 文件中的模型、当前文本服务的默认模型。语言变体不单独覆盖模型设置。“恢复默认”使用与运行时一致的默认 Prompt；已有自定义 Prompt 和 Skill 在桌面版升级时保留。

调整这些规则只影响以后重新分析产生的建议。分析 Agent 仍只读取上下文并保存衔接元数据，不能拆分、改写分镜或提示词、读写文件或生成视频；来源、能力、版本冲突和人工选择的保护由代码校验。

## 三种生成方式

| 方式 | 适合情况 | 模型条件 |
| --- | --- | --- |
| 独立生成 | 首段、换场景、换时间、正常换机位 | 使用当前视频模型 |
| 尾帧接续 | 下一段需要从前段明确的姿势或构图开始 | ComfyUI H3 或 Wan 2.2 5B |
| 动作上下文 | 同场景、相近机位，延续进行中的动作 | ComfyUI MiniMax H3 |

来源只能是同集紧邻的前一个有效段落。首段必须独立；换场景或换时间也使用独立生成。动作上下文与首尾帧图片约束互斥。条件不满足会返回明确阻挡原因，不会自动改用其他方式。

H3 的每次新任务都保存独占的 latent 路径和兼容信息。旧共享目录的上下文不能视为已验证，但旧视频仍可播放、导出或提取尾帧。前段换了视频版本后，已完成后段继续引用原来的版本，并提示来源已更新。

## 任务状态与恢复

- `queued`：已入队；有依赖时等待前段完成。
- `processing`：准备素材、提交或轮询上游。
- `downloading`：正在保存已生成的视频。
- `completed`：生成完成；旧任务晚到或输入已变化时只存为历史，不覆盖当前视频。
- `failed` / `blocked`：失败或执行条件不满足。来源失败会阻挡对应后继，独立分支可以继续。
- `cancelled`：本地任务和发布权已取消。已提交的远端任务可能仍在运行，系统不调用影响其他任务的 ComfyUI 全局中断。

提交状态待确认时，使用“核查上游任务”。该操作仅在原 ComfyUI 实例查询原请求键，不重新提交 GPU 任务。查到唯一匹配后继续原任务；未查到则保持阻挡。请勿靠反复点击普通生成来绕过这个状态。

已知上游任务 ID 的轮询或下载失败，重试会复用原任务 ID 恢复查询、下载；需要真正重新生成时创建新版本。“继续未开始的后续任务”只重绑尚未提交的后继，保留已提交任务的原来源。

## 导出连接与实际时长

| 连接方式 | 默认值 | 时间轴行为 |
| --- | --- | --- |
| 直接切镜 | 0 ms | 保留完整片段时长 |
| 短画面叠化 | 250 ms | 画面、音频重叠，总时长扣除重叠部分 |
| 仅音频短淡化 | 30 ms | 各段边缘淡出、淡入，不重叠，不缩短画面 |

叠化按输出帧率量化，上限为 500 ms 与较短片段四分之一中的较小值；音频边缘淡化不超过 100 ms。部分选段跳过中间片段时，新形成的边界默认直接切镜，可在本次导出中明确覆盖。

导出统一画布、帧率和 48 kHz 双声道，缺失音轨补静音；缺失视频直接阻挡，不悄悄跳过。实际归一化帧数决定时间轴：`成片时长 = 各段实际时长之和 − 叠化重叠时长之和`。普通剪切和音频边缘淡化不扣时长。

当前 H3 基础工作流有帧数网格，动作上下文节点还会裁掉已重叠的前缀。本次未修改该基础图或 Python 节点，因此“请求 6 秒”不等于“交付恰好 6 秒”；一次隔离实测得到独立段 158 帧、动作续段 136 帧，均为 24 fps。导出按实际视频帧数处理，不重复裁掉 H3 的重叠前缀。

## 接口与兼容

- `POST /episodes/:id/analyze-continuity`：分析现有分镜，仅保存衔接元数据。
- `PUT /storyboards/:id`：提交 `continuity_plan` 或 `transition_config` 时携带 `continuity_revision`。
- `POST /tasks/batch/preview`：预检依赖和素材；`POST /tasks/batch` 使用 `request_key` 一次入队。
- `POST /tasks`：单段视频使用同一持久队列，保留原入口。
- `POST /tasks/:id/retry`、`/cancel`、`/reconcile`：恢复、取消、核查上游；可选 `continue_dependents` 控制未提交后继。
- `POST /storyboards/:id/continuity-frame`：空请求体使用立即前序当前视频；可选正整数 `source_task_id` 指定该前序的有效历史版本。
- `POST /merge/episodes/:id/preview`、`/merge`：可传 `storyboard_ids` 和本次 `transitions`。

旧数据默认独立生成、直接切镜。SQLite 在增量迁移前通过 backup API 保存一致性备份；重复启动不会重复迁移。迁移不会自动重新生成已有视频。

## 效果边界

连续性控制能传递指定来源的画面、动作上下文和状态，仍不能保证模型完全遵循人物、道具、机位或对白要求。隔离样片的两个接续边界保留了主要位置关系，但仍出现纹理重绘和提示词未要求的人物。正式成片应检查接缝画面与声音。

短音频淡化用于缓和边缘变化，不会补回被截断的台词；本次没有对白分轨、真正的 J/L 剪辑或跨集自动接续。
