# ショット連続性分析ガイド

この Skill は `continuity_planner` が隣接する2つの絵コンテ段落の境界を判断するためのものです。根拠の優先順位、保守的な選択、小さなケースを示します。作業手順とツールの順序は System Prompt に従います。

## 判断チェックリスト

1. 2つの絵コンテが同じエピソードに属し、現在の段落が直前の段落であることを確認します。接続元は同一エピソードの直前段落の実際のデータベース `id` だけです。`shot_number` を使ったり、段落を飛ばしたり、エピソードをまたいだりしません。
2. 前段落の最後のサブカットと現在の段落の最初のサブカットだけを比較します。段落内のカットはこの分析の対象外です。
3. 動画能力を選ぶ前に画面上の根拠を確認します。能力は `readStoryboardContext` が返す `video_model.supported_modes` だけを使います。
4. 関係を決めてからモードを決めます。
   - 同じシーンで画角、アングル、クローズアップ、切り返しが変わる場合は通常 `same_scene_cut` + `independent` です。独立生成の source は `null` です。
   - 同じカメラで境界をまたいで動作が明確に続く場合だけ `continuous_action` + `motion_context` にし、能力が対応している場合だけ使います。
   - 前段末尾の構図、人物の位置、姿勢を明確に引き継ぐ場合だけ `tail_frame` にし、能力が対応している場合だけ使います。
   - シーン変更は `scene_change` + `independent`、時間変更は `time_change` + `independent` です。どちらも source は `null` です。
   - 根拠が不明、または能力リストが空の場合は `unknown` + `independent`、`needs_review: true` にします。
5. 人物の位置、向き、姿勢、視線、持ち物、動作の進行、カメラ位置を確認します。脚本または `description` で確認できる事実だけを書きます。重要な根拠が欠けているときは要確認とし、想像で補わず `needs_review: true` にします。
6. 先頭段落は常に `independent`、`source_storyboard_id: null` です。別エピソードの段落を source にできません。

## モードの境界

- `independent`：通常のカット、シーン／時間の変更、関係不明、対応しない能力、根拠不足に使うデフォルトの保守的なモードです。
- `motion_context`：同じカメラからの連続動作だけに使います。例えば固定のミディアムショットで人物がカップに手を伸ばし、次の段落も同じ画面から唇まで運ぶ動作を続けるケースです。サイドアングルやクローズアップへ変わるなら `independent` です。
- `tail_frame`：終了時の構図を明示的に引き継ぐ場合だけに使います。例えば前段が画面右側の人物が左を向き、手に手紙を掲げた状態で終わり、次段も同じ構図から始めてから振り向くケースです。「同じシーン」や「関係する動作」だけでは尾帧の根拠になりません。

## 小さなケース

### 同じシーンでカメラが変わる
前段の最後はリビングのミディアムショットで人物が電話を置き、現在段の最初は同じ部屋のサイドクローズアップで人物が顔を上げるケースです。`relation: same_scene_cut`、`mode: independent`、`source_storyboard_id: null` とし、カメラ変更を理由にします。motion context と誤判定しません。

### 同じカメラで動作が続く
前段の固定ミディアムショットで人物がカップを取るため手を伸ばし、現在段が同じ固定画面で手を上げ続け、動作を繰り返さないケースです。`supported_modes` に `motion_context` がある場合だけ、`relation: continuous_action`、`mode: motion_context`、前段の実際の ID を使います。対応しなければ `independent`、source `null`、`needs_review: true` にします。

### 明確な尾帧の引き継ぎ
前段の終わりに人物の位置、向き、持ち物が明確に構図化され、現在段がその構図から始まることを明示しているケースです。能力リストが `tail_frame` を支持するときだけ選び、支持しなければ独立生成として能力不足を理由にします。

### シーンまたは時間が変わる
夜のキッチンから朝の通りへ切り替わる、または同じ場所でその夜から翌日に時間が飛ぶケースです。`scene_change` または `time_change` と `independent`、source `null` にします。変化を越えて尾帧や動作コンテキストを持ち越しません。

### 根拠が足りない
前段には「外へ歩いて出る」としかなく、現在段には「振り返る」としかないうえ、位置、方向、カメラ、時刻の根拠がないケースです。`relation: unknown`、`mode: independent`、source `null`、`needs_review: true` とし、不足する根拠を `reason` に書きます。

### セリフのブリッジ
同じ出来事について質問と回答が段落をまたぐ場合など、セリフを `reason` の物語上の補助根拠にすることはできます。ただし音声のシームレス接続や J/L カットを保証するものではありません。画面上の関係からモードを選び、書き出しトランジションのツールを呼びません。

## 保存チェック

`saveContinuity` は 1〜8 件のバッチで呼び、対象をすべて一度ずつ処理します。各項目は次の形で、`readStoryboardContext` から読んだ現在の revision を使います。

```json
{
  "storyboard_id": 123,
  "continuity_revision": 0,
  "continuity_plan": {
    "mode": "independent",
    "relation": "unknown",
    "source_storyboard_id": null,
    "reason": "根拠不足のため要確認",
    "needs_review": true,
    "start_state": "要確認：…",
    "end_state": "要確認：…"
  }
}
```

manual の選択、revision、脚本、絵コンテの説明、動画プロンプト、動画ファイル、書き出しトランジションを追加・変更しません。既存の manual 選択はサービスが保持し、AI 分析は suggestion だけを追加します。一般的な引数エラーなら返されたフィードバックに従って修正し、未保存の対象だけを続けます。revision の競合ならこの分析を停止し、更新して再試行するよう伝え、すでに正常に保存された提案を保持したまま、この実行が完了していないことを明示します。成功を捏造しません。
